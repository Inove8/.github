# Contributing to Inove8 projects

Thanks for taking the time to contribute! These guidelines apply to every repository in the Inove8 organisation unless a repo has its own `CONTRIBUTING.md`.

## Workflow

1. **Open an issue first** for anything bigger than a typo, so we can agree on the approach.
2. **Branch from `main`** using a descriptive name: `feat/…`, `fix/…`, `chore/…`, `docs/…`.
3. **Write clear commits** following [Conventional Commits](https://www.conventionalcommits.org/) — e.g. `feat(auth): add OTP login`.
4. **Open a pull request** using the PR template. Keep PRs small and focused; link the related issue.
5. **Pass checks** — lint, tests and build must be green before review.
6. **Get one approval** from a code owner, then squash-merge.

## Code standards

- Follow the formatter/linter config in each repo (Prettier, ESLint, PHP-CS-Fixer, etc.).
- Never commit secrets, `.env` files, API keys or client data.
- Add or update tests for behaviour changes.
- Update docs and the README when you change how something is used.
